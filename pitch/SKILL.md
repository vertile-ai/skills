# Pitch

## Core Rule

Do not write persuasive copy until the user's real selling point is known.

Treat selling points as supplied facts, not as creative blanks. If the user has not provided a specific audience, benefit, differentiator, proof, or outcome, ask for the missing pieces before drafting. Never invent metrics, traction, customer pain, novelty, market size, social proof, scarcity, or urgency.

## Workflow

1. Identify the output type: README, short video script, presentation pitch, elevator pitch, launch copy, landing-page copy, or another persuasive format.
2. Extract the user-provided selling point(s). Preserve the user's wording when it carries important nuance.
3. Classify each selling point:
   - Audience: who cares.
   - Pain: what they struggle with now.
   - Outcome: what improves.
   - Differentiator: why this is not interchangeable.
   - Proof: demo, metric, customer, benchmark, implementation detail, or credible constraint.
   - Action: what the reader/viewer should do next.
4. If the selling point is missing or too generic, ask concise clarification questions and stop before drafting.
5. Put the strongest verified selling point in the first sentence, first heading, first slide, or first 3-5 seconds.
6. Draft from value to evidence to action: hook, proof, explanation, next step.
7. Run the no-fabrication check before finalizing.

## Clarification Gate

Ask only for information needed to avoid fake selling. Use up to three questions:

- What exact audience should this pitch win over?
- What is the strongest real benefit, result, or pain relief this offers?
- What proof or differentiator can be stated honestly?

If the user gives raw notes, infer structure but do not create unsupported claims. Label uncertain items as "needs confirmation" instead of using them as facts.

## First 3-5 Seconds

The opening must answer one of these immediately:

- "Why should this person care?"
- "What painful thing becomes easier?"
- "What can this do that alternatives do not?"
- "What proof makes this credible now?"

Prefer this shape:

```text
[Audience] can [desirable outcome] without [pain/tradeoff], using [specific differentiator or proof].
```

Avoid slow openings:

- Background before value.
- Generic mission language.
- Feature lists with no user benefit.
- "Hi, today I will..." intros.
- Unproven superlatives like "best", "revolutionary", or "game-changing".

## Format Guidance

Read `references/patterns.md` when drafting actual copy. Use only the relevant section:

- README: lead with usefulness, then what it does, quick start, proof, examples.
- Short video: open with payoff or tension, show the product/subject early, keep one message, end with a direct action.
- Presentation pitch: one-sentence purpose, problem, solution, why now, proof, ask.

## No-Fabrication Check

Before final output, verify:

- The first sentence or first 3-5 seconds contains a real user-provided selling point.
- Every metric, comparison, proof point, and differentiator was provided or can be cited from supplied material.
- The audience is specific enough to make the benefit meaningful.
- The copy says what to do next.
- Any assumptions are marked as assumptions or turned into clarification questions.

If the check fails, ask for clarification instead of filling gaps.
